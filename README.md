# API Inventarios

Microservicio REST para la gestión de inventario de componentes (CloudTech). Forma parte de un sistema de microservicios junto a `api-compras`.

## Tecnologías

- Java 17+ / Spring Boot 3
- Spring Data JPA (Oracle Database)
- Lombok
- SpringDoc OpenAPI (Swagger)
- RestTemplate (comunicación con `api-compras`)
- Jakarta Validation

## Estructura del proyecto

```
cl.duoc.api_inventarios
├── Controller/      → ComponenteController
├── Service/         → ComponenteService
├── Repository/      → ComponenteRepository
├── Model/           → Componente, ComponenteDTO, OrdenDTO, Auditoria
├── exception/       → GlobalExceptionHandler
└── config/          → OpenApiConfig
```

## Modelo de datos

### Componente
| Campo | Tipo | Validación |
|---|---|---|
| id | Long | autogenerado |
| fabricanteId | String | `@NotBlank`, único |
| nombre | String | `@NotBlank` |
| precio | Float | `@Positive` |
| unidades | Integer | `@PositiveOrZero` |
| estado | String | `En_Stock\|Asignado\|Agotado` |
| idBodega | Long | `@NotNull` |

### ComponenteDTO
Respuesta resumida de stock: `nombre`, `unidades`, `estado`, `ordenesEnTransito` (List<OrdenDTO>).

### Auditoria
Entidad preparada para registrar cambios de estado/unidades. Tabla ya creada en BD (ver script DDL), pero `@Entity`/`@Table` siguen comentados en el código — falta descomentar y habilitar `AuditoriaRepository`.

## Endpoints

Base path: `/api/v1/inventarios`

| Método | Ruta | Descripción |
|---|---|---|
| POST | `/` | Registrar nuevo componente |
| GET | `/` | Listar todos los componentes |
| GET | `/{id}` | Buscar componente por ID |
| GET | `/stock/{id}` | Consultar stock (DTO) de un componente |
| PUT | `/{id}` | Actualizar componente |
| DELETE | `/{id}` | Eliminar componente |

### Reglas de negocio

- **Creación**: rechaza si `fabricanteId` ya existe (`existsByFabricanteId`).
- **Consulta de stock**: si `unidades < 3`, consulta `api-compras` para obtener órdenes en estado `EN_TRANSITO` o `ADUANA` del mismo `fabricanteId`. Si la API externa falla, se captura la excepción y se responde igual (sin órdenes).
- **Eliminación**: rechazada si el componente está en estado `Agotado` (registro contable congelado para cierre ISO de fin de año).

## Integración externa

`ComponenteService` consume `api-compras` vía `RestTemplate`:

```
GET http://localhost:28099/api/v1/proveedores/fabricante/{fabricanteId}
```

## Manejo de errores

`GlobalExceptionHandler` (`@RestControllerAdvice`) centraliza las respuestas de error:

| Excepción | HTTP Status |
|---|---|
| `IllegalArgumentException` | 400 Bad Request |
| `NoSuchElementException` | 404 Not Found |
| `Exception` (genérica) | 500 Internal Server Error |

Cuerpo de respuesta estándar: `fecha`, `status`, `error`, `mensaje`, `ruta`.

## Logging

Uso de `@Slf4j` (Lombok) en controller y service, con niveles diferenciados:
- `INFO`: recepción de peticiones, operaciones exitosas
- `DEBUG`: detalle de consultas
- `WARN`: errores de cliente / reglas de negocio
- `ERROR`: fallos críticos o de integración externa

## Script de creación de base de datos (Oracle)

```sql
-- =========================================================
-- CREACION DE TABLAS PARA LA API INVENTARIO
-- =========================================================

-- BORRADO DE TABLAS SI EXISTEN (Prevención de errores)
BEGIN EXECUTE IMMEDIATE 'DROP TABLE AUDITORIA CASCADE CONSTRAINTS'; EXCEPTION WHEN OTHERS THEN NULL; END;
/
BEGIN EXECUTE IMMEDIATE 'DROP TABLE COMPONENTES CASCADE CONSTRAINTS'; EXCEPTION WHEN OTHERS THEN NULL; END;
/

-- =========================================================
-- CREACIÓN DE LA TABLA: COMPONENTES
-- =========================================================
CREATE TABLE COMPONENTES (
    ID              NUMBER(20)      GENERATED BY DEFAULT AS IDENTITY,
    ID_FABRICANTE   VARCHAR2(30)    NOT NULL,
    NOMBRE          VARCHAR2(100)   NOT NULL,
    PRECIO          NUMBER(10, 2)   NOT NULL,
    UNIDADES        NUMBER(10)      NOT NULL,
    ESTADO          VARCHAR2(20)    NOT NULL,
    ID_BODEGA       NUMBER(20)   NOT NULL,

    -- Restricciones de Integridad
    CONSTRAINT PK_COMPONENTES PRIMARY KEY (ID),
    CONSTRAINT UK_COMP_FABRICANTE UNIQUE (ID_FABRICANTE),               -- Mapeo de unique = true
    CONSTRAINT CHK_COMP_PRECIO CHECK (PRECIO > 0),                      -- Mapeo de @Positive
    CONSTRAINT CHK_COMP_UNIDADES CHECK (UNIDADES >= 0),                 -- Mapeo de @PositiveOrZero
    CONSTRAINT CHK_COMP_ESTADO CHECK (ESTADO IN ('En_Stock', 'Asignado', 'Agotado'))  -- Mapeo de @Pattern
);

COMMENT ON TABLE COMPONENTES IS 'Tabla principal que almacena el inventario de componentes.';
COMMENT ON COLUMN COMPONENTES.ID_FABRICANTE IS 'Identificador único provisto por el fabricante.';
COMMENT ON COLUMN COMPONENTES.ID_BODEGA IS 'Referencia a la bodega donde se encuentra almacenado el componente.';

-- =========================================================
-- CREACIÓN DE LA TABLA: AUDITORIA
-- =========================================================
CREATE TABLE AUDITORIA (
    ID                  NUMBER(20)      GENERATED BY DEFAULT AS IDENTITY,
    COMPONENTE_ID       NUMBER(20)      NOT NULL,
    ESTADO_INICIAL      VARCHAR2(50),
    ESTADO_DESPUES      VARCHAR2(50)    NOT NULL,
    UNIDADES_INICIAL    NUMBER(10),
    UNIDADES_DESPUES    NUMBER(10),
    FECHA_REGISTRO      TIMESTAMP(6)    DEFAULT SYSTIMESTAMP NOT NULL,

    -- Restricciones de Integridad
    CONSTRAINT PK_AUDITORIA PRIMARY KEY (ID),
    -- Relación lógica con la tabla COMPONENTES
    CONSTRAINT FK_AUDIT_COMPONENTE FOREIGN KEY (COMPONENTE_ID) REFERENCES COMPONENTES(ID)
);

COMMENT ON TABLE AUDITORIA IS 'Tabla transaccional para el registro de cambios históricos en los componentes.';
COMMENT ON COLUMN AUDITORIA.FECHA_REGISTRO IS 'Fecha y hora exacta del cambio, asignada por @PrePersist en Java o por defecto en BD.';
```
